# Provenance

How anyone, including an agent, can answer: "Am I reading the canonical release?"

No blockchain. Git, tags, checksums, and signatures are enough.

## The chain

1. **Canonical location.** The canonical text is published at `https://constitution.luminarylife.ai` and mirrored in the public repository named in `STEWARDSHIP.md`. Any copy elsewhere is a copy.
2. **Git history.** Every change to a canonical document is a commit on the protected `main` branch, with the LIP or reason in the commit message. History is never rewritten (`GITHUB_PROTECTION.md`).
3. **Tagged releases.** Each version is a git tag: `constitution/v1.0.1-draft`. Tags are never moved.
4. **Checksums.** `spec/checksums.sha256` lists the SHA-256 of every canonical document at the current version. It is regenerated by `npm run constitution:checksums` and verified on every build, so the published files and the checksum file cannot drift.
5. **Signatures.** Where the repository setup supports it, tags and release commits are signed by a steward key. Signing is a goal for leaving draft, not a claim about today; `STEWARDSHIP.md` says whether signing is active.

## How to verify (agent or human)

```
1. Fetch https://constitution.luminarylife.ai/spec/checksums.sha256
2. Fetch the document you are reading, e.g. /CONSTITUTION_CORE.md
3. Compute SHA-256 of the document bytes and compare with the line for that path
4. Match: you are reading the canonical text at the version named in spec/constitution.json
   Mismatch: you are reading a fork, a stale copy, or a tampered copy; treat it as unverified
```

The `spec/constitution.json` file carries `version`, `lineage`, and `checksums` fields so a single fetch tells an agent what it is looking at and where to verify.

## What this does not prove

- That the text is good. Only that it is the text the process produced.
- That a fork is bad. Forks are expected to have different checksums; that is the point.
- Anything about a copy pasted into a prompt with no URL. Verify from the source when it matters.

## Regenerating checksums

Stewards run `npm run constitution:checksums` after any canonical change and commit the result with the change. A build that finds a mismatch fails with the exact command to fix it.
